# 定位同步失败

登录成功只证明账号验证通过；新增记录还需要上传接口和数据库写入成功。空队列时显示「已同步」，不能证明新增记录一定可以上传。

## 让同学提供什么

更新应用后，先「设置 → 立即同步」，再「同步诊断 → 复制诊断」或「下载诊断」。报告包含账号、客户端构建时间、浏览器、待上传数量、失败环节、HTTP 状态和请求编号，不包含密码、Cookie、工作内容或完整记录。旧版服务端没有请求编号时可参考 Cloudflare Ray。

保留原设备上的未同步数据。排查期间不要清缓存、退出登录或从云端重建；需要备份时先导出 CSV。

| 诊断结果 | 优先检查 |
|---|---|
| 上传 / DATABASE_SCHEMA_OUTDATED / 503 | 执行缺少的数据库迁移 |
| 上传 / VALIDATION_ERROR / 400 | 对照错误提示检查记录字段与客户端版本 |
| 401 | 登录状态、Cookie、是否使用同一个正式网址 |
| 403 | 同源校验或 Cloudflare 安全拦截；结合 Ray 与日志区分 |
| 500 / INTERNAL | 用请求编号查询服务端异常 |
| NETWORK_ERROR、TIMEOUT | 当前网络、代理、DNS、访问是否超时；无服务器编号通常是请求未完成 |
| UNEXPECTED_RESPONSE | 请求收到网页或非预期数据，核对网址、代理与前后端版本 |
| 本机数据环节 | 浏览器存储访问异常；保留当前浏览器，先导出已有数据 |
| RECORD_*、INCOMPLETE_RESPONSE | 保留待同步队列，结合关联记录编号和请求编号检查 |

## 服务端日志

开一个终端监听，保持运行，再让同学点击「立即同步」：

```bash
node scripts/wrangler.mjs pages deployment tail --project-name worklog --environment production --format pretty
```

新代码的失败日志使用 `api_request_failed`，包含请求编号、账号内部 ID、请求路径、错误码和状态；服务端异常另带错误原因，不记录请求体、密码或 Cookie。用同学提供的请求编号对应同一条日志。

若终端没有对应请求，同时客户端报告网络失败，先看网络和 Cloudflare 的安全事件。不能仅凭没有应用日志就断言是某个浏览器的问题。

## 对照验证

同一账号分别新建一条 2h 值班、1.5h 值班和独立加班，记录每次操作时间及结果；换设备登录后确认记录实际出现，才算完成上传与下载验证。不要用反复换浏览器替代错误诊断。

失败或被拒绝的上传现在会保留操作队列并显示失败，不会因服务器拒绝而静默移出队列或显示「已同步」。仍可在本机修改后重试。
